# RAG 阶段三实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task with TDD checkpoints.

**Goal:** 将阶段二的 15,000 条 embedding artifact 导入独立 PostgreSQL + pgvector，并提供可验收的精确向量、HNSW、PostgreSQL FTS、公式、过滤和 RRF 检索能力。

**Architecture:** RAG 使用独立 `RAG_DATABASE_URL`、独立 `rag_migrations/`、独立 Compose 文件、独立数据库 volume 和 `rag` schema。artifact 先校验 manifest、SHA-256、字段关联和向量维度，再以 corpus 版本方式导入；查询只读取 `active` corpus，失败导入不会覆盖旧版本。中文 FTS 采用稳定的预处理词法管线并存储管线版本，RRF 在应用层融合各召回通道。

**Tech Stack:** Python 3.13、SQLAlchemy 2、psycopg 3、Alembic、PostgreSQL 17、pgvector、pytest。

## Global Constraints

- RAG 必须使用独立 PostgreSQL + pgvector，不修改 Memory Alembic、Memory 数据表、原有 Compose 或 Memory volume。
- 配置只读取 `RAG_DATABASE_URL`，不得回退读取 `DATABASE_URL`。
- 向量固定为 `text-embedding-v4`、1024 维、cosine distance；chunk 参数已经固定为 size 800、overlap 100。
- `answer_key` 的 `retrieval_weight` 必须保持 0.65，其他主检索内容为 1.0。
- 所有新建或修改的代码模块添加简体中文模块注释；artifact 大文件不提交 Git。
